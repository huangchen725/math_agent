# 工作红线触发与阻断协议

> 权威规则正文：`docs/ENGINEERING_SPECIFICATION.md`
>
> 本文件只规定工作 agent 如何发现、报告和阻断规则触发，不定义运行架构。

## 每次工作的强制前置

任何 agent 在读取任务后、修改文件或运行有副作用命令前，必须：

1. 读取根 `AGENTS.md` 和本文件。
2. 列出预计修改或执行涉及的文件/表面。
3. 运行 `python .agents/policy_guard.py --paths <path...>`；涉及纯外部动作时增加或单独使用 `--actions <action...>`，例如 `real-api`、`push`、`official-submit`、`release`。尚不能确定路径时，至少按下表人工匹配。
4. 在工作更新中列出触发的规则 ID、当前恢复阶段和允许的动作边界。

## 触发后的强制行为

发现拟执行动作会违反 blocker 时，agent 必须在执行前明确输出：

```text
[POLICY BLOCK] <RULE-ID>
触发动作：<准备执行的具体修改、命令或发布动作>
风险：<会破坏的契约或可能造成的正式后果>
处理：已停止该子动作；将采用 <安全替代>，或等待 <必要证据/授权>。
```

随后停止违反规则的子动作。任务中仍有不触线的部分时继续完成安全部分，不得因为阻断一项就放弃全部工作；也不得静默改写方案、先执行后补报或用测试通过掩盖触线事实。

普通用户授权只能覆盖费用、联网、推送等需要授权的动作，不能直接豁免赛事资格、安全、秘密、数据泄漏、官方接口和正式发布底线。确需改变底线时，必须先取得对应官方书面证据或新的明确项目决策，单独更新规则、测试和证据状态，再开始实现。

## 触发表

| 工作表面 | 自动触发规则 | agent 必须先确认 |
| --- | --- | --- |
| `user_agent.py`、client、gateway、入口加载 | `ANCHOR-001`、`IMPORT-001/002`、`CLIENT-001/002`、`ENTRY-001/002` | 当前阶段是否允许改运行时；是否只使用三参数公开协议；是否存在类身份提权、私有读取或同名碰撞 |
| 新增/移动/重命名 Python 模块 | `IMPORT-001`、`TEST-IMPORT-001`、`CHANGE-001`、`DOC-001` | 是否使用唯一前缀；是否同时改变求解行为；导入闭包和污染矩阵是否存在 |
| prompt、模型、候选、温度、token、工具、聚合 | `CHANGE-001`、`EVAL-001`、`API-AUTH-001` | 是否只有一个实验变量；是否冻结数据、配置和成本；真实 API 是否另获授权 |
| parser、normalizer、equivalence、validator、状态机 | `PBT-001`、`SECURITY-001` | 是否使用 property-based-testing；是否有固定历史反例和最强可验证性质 |
| 题集、判分、盲测、成绩声明 | `DATA-001`、`EVAL-001`、`EVIDENCE-001` | 来源/许可/split/难度/去重是否完整；是否泄漏；0 请求是否被错误计入能力 |
| 官方材料、模型/接口规则、赛事结论 | `OFFICIAL-001`、`EVIDENCE-001` | 是否先记录原文、日期、适用批次和 SHA；是否错误关闭 `OFFICIAL-GAP-*` |
| 依赖、CI、锁、发布、提交/推送 | `SUPPLY-001`、`RELEASE-001`、`SUBMIT-001` | 锁与输入是否同步；是否干净提交；远程 SHA 和提交窗口是否冻结；是否获得外部动作授权 |
| 文档、规范、Skill | `POLICY-001`、`DOC-001`、`SKILL-001` | 是否仍只有一个架构事实源；所有项目 Skill 是否加载本协议；机器清单与文本规则是否同步 |

无文件变更的真实 API、Git 提交/推送、正式提交、发布、依赖调整、官方材料处理和 benchmark 工作同样必须用 `--actions` 触发，不得以“工作树干净”为由跳过。

## 修改后的强制复核

完成编辑后运行：

```bash
python .agents/policy_guard.py --changed
```

该命令必须打印本次涉及的规则 ID。退出码非零时，agent 必须按 `[POLICY BLOCK]` 格式报告并修复，不得提交。

正式候选还必须二选一：

```bash
# 仅核对历史锚点内容（R0 已于 2026-09-05 完成并消耗定锚例外）
python .agents/policy_guard.py --anchor-canary

# R1 起改动版的完整正式检查
python .agents/policy_guard.py --formal
```

`--anchor-canary` 只验证活动运行时仍与 `350a267f` 一致，不证明旧请求参数、trace 或截断边界安全；运行时在 R1 加固中偏离锚点后，该检查即不再适用。`--formal` 自 2026-09-05 阶段进入 R1 起作为正式改动版门禁；改动版必须先完成 `CLIENT-001` 三参数投影等加固项才能通过。

## 证据不足时

- 不知道平台行为：保留相应 `OFFICIAL-GAP-*`，采用最小公开契约。
- 不知道某项改动是否提升正确率：标记实验，先建配对盲测。
- 不知道是否触线：按更严格规则阻断该子动作，并明确向用户报告不确定点。
- fake client 或离线测试通过：只能关闭对应本地回归，不能关闭正式平台缺口。
