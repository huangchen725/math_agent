## 不可触碰的边界

1. 不得由人工对评测题逐题选择、改写或补充答案。
2. 不得在评测结束后补填结果，也不得把人工创建的 checkpoint 当成模型输出。
3. 不得伪造、拼接或改写运行日志。正式提交的日志和结果必须来自同一次自动运行并保留原始文件哈希。
4. 不得用未经允许的外部闭源服务代答。运行时只允许赛事官方注入客户端、官方 Intern API 和本地受限 SymPy 工具。
5. 正式参赛配置使用 `intern-s1`。现有 `intern-s2-preview` 记录仅是历史开发实验；除非主办方书面明确允许，否则不得用作正式模型或 formal 交付包声明。
6. 每题必须返回可解析 JSON，包含非空 `final_response` 和列表 `trace`；最终文本必须以唯一的非空 `最终答案：...` 行结束。
7. 公开 `trace`、标准输出和标准错误不得作为隐藏题或模型交互回传通道；题面、prompt、模型/候选/verifier/critic/tool 正文、最终答案、异常消息和敏感字段不得进入 trace。

违反前四项属于资格风险，不能用更高正确率、人工复核或赛后说明抵消。第五、六项属于当前手册下的正式验收阻断项。

## 已固化的工程控制

| 风险 | 项目控制 | 离线证据 |
| --- | --- | --- |
| 参考答案泄漏给 Agent | `main.solve_item` 只传题面和 `idx`，不传 `answer`、`reference_solution` 等字段 | `scripts.check_competition_compliance` 使用哨兵答案验证隔离 |
| 非 S1 被误当作正式模型 | 默认模型和 `.env.example` 固定为 `intern-s1`；参赛模式默认开启 | 客户端在参赛模式拒绝非 S1；formal 打包再次拒绝 |
| 未授权外部服务 | 自有客户端只接受官方 HTTPS Chat Completions 地址；工具均在本地受限子进程执行 | 合规门禁扫描运行时网络依赖和 URL |
| 格式导致直接未通过 | 输出构造、runner 和回归测试验证 JSON、非空答案及唯一末行标记 | 合规门禁执行无网络契约探针 |
| 注入客户端在请求前失败 | 未知 client 只收到 `messages/temperature/max_tokens`；自有扩展按项目类型选择，不做签名/marker 探测 | 无 `**kwargs` 的三参数 fake 与私有访问抛错 fake 均必须产生公开 chat 调用；工具槽须显式文本降级 |
| 独立 worker 无法导入包门面 | 根 `user_agent.py` 按自身文件目录引导唯一 `math_agent/` 包 | 隔离解释器从仓库外按绝对路径动态加载入口 |
| trace 泄露题面或模型正文 | 返回前通过元数据白名单失败关闭投影，未知事件/字段不外发 | 固定题面、模型、verifier 和答案哨兵；投影幂等且可 JSON 序列化 |
| 私有数据或结果混入源码包 | 发布白名单排除 `.env`、`outputs/`、`.quality/` 和 `dist/` | formal 包要求合规门禁通过并二次扫描 |
| 日志被赛后改写 | 运行摘要保存输入文件 SHA-256、模型、计数和时间；原始评测产物单独留存 | 提交前按下方清单生成并核对文件哈希 |

`COMPETITION_MODE=0` 只表示本地非提交实验，不能证明该实验符合赛事模型要求。此模式仍不允许改用第三方 API 地址，也不能绕过正式打包的 S1 检查。

## 正式运行前

- 使用全新输出目录，不复制、预置或手工创建任何题目结果文件。
- 确认 `COMPETITION_MODE=1`、`INTERN_MODEL=intern-s1`，并确认调用的是官方端点或赛事注入客户端。
- 固定干净 commit、输入数据 SHA-256、配置、并发、开始时间和预计请求上限。
- 用隔离入口门禁确认 `user_agent.py` 不依赖 judge 当前目录，并确认无 `**kwargs` 的三参数 injected-client 回归实际调用公开 `chat()`，且每次只收到三个允许参数。
- 运行 `python -m scripts.run_quality_gates`；不得删除 `competition_compliance`、格式或接口检查来换取通过。
- 若主办方书面批准其他模型或服务，把原始答复与日期归档，再通过正常代码评审更新本文件和门禁；不得只改环境变量或打包参数。

## 正式运行与留证

- 运行期间不得根据单题内容暂停后改 prompt、切模型、选择候选或重新提交某一道题。
- 基础设施故障只能按事先冻结的全局重试规则处理；规则变更后必须整批重新运行并区分版本。
- 保留平台原始日志、runner 结果、运行摘要和错误记录。不要在原文件上“修正格式”；需要重算统计时生成新文件，并记录输入文件哈希和工具版本。
- 人工盲审只能作为独立评估材料，不能回写模型答案或冒充自动正确率。

## 提交前四眼核对

1. 两人分别确认模型、端点、commit、数据哈希和质量报告一致；个人参赛时至少分两次独立核对并留下时间记录。
2. 对每个提交日志、结果 JSON、技术报告、演示视频和压缩包计算 SHA-256，写入只追加的提交清单。
3. 随机抽查结果 JSON 能解析、字段完整、`final_response` 非空；不得人工修复抽查到的单题，发现问题应修代码后整批重跑。
4. 确认没有 `.env`、token、私有题面、人工答案表、临时补丁或非授权服务配置进入提交包。
5. 抽查公开 `trace` 只有结构化元数据，不含题面、prompt、模型/工具正文、最终答案或异常消息。
6. 用正式命令生成源码包。若 manifest 状态为 `draft`、模型不是 `intern-s1`、质量报告不完整或工作树不干净，停止提交。

## 尚不能由代码证明的事项

离线门禁可以阻止常见误配置并留下可审计证据，但不能证明操作者从未在代码外人工干预，也不能替代主办方对模型或外部服务的授权。正式提交仍需保存原始平台记录、书面授权和人工操作日志；缺少这些证据时应按不获授权处理。
