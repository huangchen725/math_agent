## 截断根因

当前候选提示要求先写推理、最后写 `最终答案`。当难题回复撞到 8,192 token 平台上限时，答案行可能根本没有生成。与此同时，旧 `_extract_answer()` 在找不到显式答案标记时，会把回复最后一个非空行截取为“答案”。因此：

1. 截断候选可能被误认为具有有效答案；
2. 全候选无答案时的快速回退可能不触发；
3. 推理残句参与多数分组或最高置信度选择；
4. 最终响应虽然会追加规范答案行，答案体却可能是截断残句，形成 `invalid`。

这个解释与日志的 106 次截断一致，也与项目历史 commit `143123f` 的经验一致：该版本曾通过关闭 thinking mode 和答案先行缓解 38% 截断。本次 thinking mode 已关闭，但 35B 在隐藏难题上仍频繁耗尽输出长度，因此需要恢复答案先行协议。

## 已实施的保守修复

本次只修改截断处理，不改变模型、候选数量、温度、thinking mode、8192 token 上限、工具轮数或聚合规则：

- 候选与反思提示要求第一行先写 `最终答案：XXX`，随后再写紧凑推理；
- `_extract_answer()` 只接受明确答案标记或 `\boxed{}`，不再把无标记末行当答案；
- 快速回退仅接受显式答案，或不超过 200 字符的单行裸答案；
- 客户端记录 `finish_reason`，单题预算摘要新增 `truncated_responses`，离线评分器同步汇总该字段；
- 对答案先行到外部“推理 + 唯一末尾答案”的转换、截断残句拒绝和截断计数增加回归测试。

外部接口契约保持不变：最终 `final_response` 保留获胜候选推理，并且只在末尾保留一行规范化 `最终答案：...`。
