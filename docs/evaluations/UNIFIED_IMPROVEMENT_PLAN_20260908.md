## 1. 目标与现状

目标是提高最终正确题数，并控制 invalid、耗时和请求成本。离线测试通过、检索命中、产生过正确候选，都不能单独替代最终正确率。没有足够证据承诺特定提分幅度或满分。

开发以当前可追溯分支为起点，基线配置先关闭全部新实验开关。首轮不主动改变已确认的 `thinking_mode=False`、8192 单次输出上限、三候选、温度及总请求预算。修改预算或选择规则各自作为独立实验。

## 2. 两条线如何组成一个系统

拟议功能流程：**题面与条件确认 → 可选公开参考 → 三个候选解答 → 数学核验 → 证据选答 → 必要的有界纠错与复核 → 最终交付**。这是功能关系，不表示所有步骤已经接入，也不要求一次提交同时改变整条流程。

- 检索线补充定理、已解例题和相似方法；初版只向一个候选添加参考，另外两个保持无检索，便于观察错误是否被共同传播。
- 求解线负责解析条件、实际计算、独立方法和候选选择；有检索与无检索候选都接受相同的数学核验。
- 检索相似度不是数学正确性的证明；精确计算也必须与原题的完整条件绑定。
- 没有可用参考时走原求解流程；不支持的数学核验返回 unknown，不强行判错。

## 3. 检索线：K1–K4

采用 K 编号，避免与已有 R1 恢复阶段混淆。

| 编号 | 改动范围与交付物 | 验收或继续条件 |
| --- | --- | --- |
| K1 公开语料 | 首个领域选择线性代数，目标 100–200 条定理、已解例题或习题卡。每条保存完整条件、解法、结论、来源、章节/题号、许可、版本和指纹 | 来源及对应文件许可核对完整；抽取前后公式、数值和条件一致；无评估题或近重复污染 |
| K2 本地检索 | CPU 本地只读索引；词项/BM25 或字符检索，加中英文数学术语。区分完整同题与相似方法；保留数值、符号、定义域、量词和维数 | 审查 12–24 个独立公开查询，至少一半 top-2 参考确有帮助；20 个改条件反例中同题误匹配为 0。均为试验门槛，不证明总体零风险 |
| K3 检索辅助求解 | 默认关闭的独立开关；仅向一个候选添加至多两条参考，总量起步不超过 6000 字符，记录实际 token；不新增模型调用 | 正确增益大于错误迁移，且完整流水线能保留收益；无命中时行为与基线一致 |
| K4 直接查表研究 | 离线评估完整同题命中、条件一致和解答正确性。直接返回库存答案的正式运行分支不纳入初版 | 库内查表成绩单独报告。正式采用该分支前须解决其具体规则边界，不能从“允许检索”直接推导已获许可 |

首批来源为 [Hefferon 的 Linear Algebra](https://hefferon.net/linearalgebra/)，作者提供完整习题解答；[许可页](https://hefferon.net/source.html) 允许选择 GFDL 或 CC BY-SA 3.0 US。按选定许可保存署名、许可及修改说明。Judson 抽象代数教材作为后续候选，教师专用解答不默认属于可用语料。

现有 U-MATH 整份来源初版不进检索库，保留既有开发/留出隔离。新增线性代数开发题来自不同来源或经审核隔离的题族，避免只用以微积分为主的 Q0 评价新语料。中文查询必须纳入检索检查，不用英文自检替代正式语言适配。

官方固定 README 鼓励检索与记忆，同时禁止读取或构造隐藏测试集、标准答案或 judger 信息。公开授权语料的检索辅助求解属于本方案范围；泄露题目、重建隐藏答案、按 idx 硬编码不属于本方案。原文、核验日期和来源边界见 [检索可行性评估](CORPUS_RETRIEVAL_PLAN_20260908.md)。

## 4. 求解线：C1–C5

| 编号 | 具体改动 | 已有基础与新增工作 | 验收重点 |
| --- | --- | --- | --- |
| C1 精确计算与检查 | 首批限定有界矩阵行列式、完整多项式求导/积分任务、组合数和模运算；随后再考虑方程全解、有理式和更复杂微积分 | 复用现有完整题型检查，补题面解析与条件绑定；审查独立计算原语后选择性接入，不能直接将整套旧工具导入正式入口 | 支持范围内结果正确；完整题意识别准确；超范围 unknown；错误候选被识别而正确候选不被误杀 |
| C2 条件与方法 | C2a 单独加入所求对象、数域、参数、边界和全解检查；C2b 单独尝试三个候选采用适用的不同方法，均输出完整答案 | 旧 diverse_candidates 同时改提示与温度，不能直接当作新方法实验。新方案保持数量与温度，独立推导不互看初解 | 初始正确候选覆盖是否提高；最终正确题数是否提高；仅措辞不同不算方法多样性 |
| C3 验证与选答 | C3a verifier 提供有界理由/反例；C3b 改善核验材料保留；C3c 独立试证据优先的选答 | 现有 calibrated_verifier 主要收紧格式；当前聚合先按一致票数。分别验证三项，不打包后归因于某一项 | 冻结候选池上的选对率、错误放行、正确误杀；完整流水线最终正确率 |
| C4 纠错与预算 | 分别测 no_critic、no_reflection；有正证据后再改针对性纠错。独立尝试为核验和交付预留时间 | 已有保留原候选和 fail 触发机制，不作为新增交付。预算预留需新实验，不全局抬高 token、超时或重试次数 | 纠错净增正确题数；预算耗尽时有效答案保留；请求/token/时间是否可接受 |
| C5 领域专用求解 | 根据公开开发题诊断，逐个补薄弱领域的解法流程、条件核查和路由 | 现有领域提示与关键词路由复用；先一个领域，观察独立题效果后扩展 | 对应领域独立题正确率，以及对其它领域的影响 |

C1 的第一批边界进一步收紧：先处理整数/有理数系数、多项式和小矩阵等可完全表达的任务；不同时承诺一般自然语言数学题的符号求解。模型生成的表达式只是待核对输入，计算原语验证一个等式也不自动证明整题解答正确。方程的一个根通过代入、积分在若干点一致、候选漏掉参数边界，都不能获得“完整证明通过”。

C2 优先覆盖已有的导数算错、曲率漏绝对值等数学反例，另配未用于调试的独立题。C3 必须保留模型判断的 unknown；普通模型反对意见不能冒充精确反例，也不能因为两份回答相同就断言正确。

C4、C5 先保持后续候选地位。若诊断发现正确候选已经很多、选答损失突出，则提前 C3；如果大部分题所有候选都错，则优先 C1/C2，随后针对薄弱领域做 C5。

## 6. 真实实验规模与成本边界

本次仅提交审核稿，真实模型请求为 0。现有三项首轮建议如下，按批独立执行、记录失败并允许随时停止：

| 实验 | 冻结输入后的执行方式 | 最多请求数 | 最大输出 token 合计 |
| --- | --- | ---: | ---: |
| B1 提示能力一致 | 4 题 × 原/新提示各 1 次，单阶段生成 | 8 | 65,536 |
| B2 简短补答 | 8 个恢复输入 × 原/新提示各 1 次 | 16 | 8,192 |
| K3 检索初筛 | 6 题 × 无/有检索各 1 次，单候选生成 | 12 | 98,304 |
| 上述三项合计 | 不包含其它策略、端到端、重复和留出实验 | **36** | **172,032** |

输入 token、服务用量和货币成本另记，未知不得填零。每批采用已有有界派发与暂停机制，无自动重试或自动续跑；最多 10 分钟派发窗口不等于承诺 10 分钟完成，已发送请求单独有界收尾。

C1 数学原语与固定候选池检查可零 API 先做。C2/C3/C4/C5、四组组合、端到端及留出没有包含在上述 36 请求中；依据前一小批结果只选最有希望的策略，再冻结对应请求数和费用范围，不默认启动全量矩阵。整题 `solve` 可能包含多次模型调用，后续预算必须按请求数计算，不能把“六题”误写成“六次请求”。

批准本方案的工程方向不自动恢复历史线上批次，也不代表已执行真实 API。执行时按用户明确批准的实验额度推进，已有有效授权不重复询问；推送和正式提交沿用原有授权边界。

## 7. 一套共同的评估与决策标准

**数据分组。** 语料内同题用于测记忆命中；改条件反例用于测误匹配；来源/题族隔离的公开开发题用于筛策略；独立留出只在候选锁定后使用。既有留出标签不参与建库或调参。参考答案只在生成结束后用于判分；候选正确性诊断不能回流到选择器。

**两条线先分开，再交汇。** 单项先对同一冻结基线做配对。分别筛出检索候选与求解候选后，同一公开小批比较“基线 / 仅检索 / 仅求解改动 / 两者组合”。这用于检查互相干扰，不能把两线收益直接相加，也不能用六题的一次正结果宣称稳定提分。

**统一指标。** 首要指标是实际最终正确数；同时记录原错新对、原对新错、unknown、无完整答案、初始正确候选覆盖、正确候选保留率、纠错前后变化、请求/token/耗时/截断。局部格式检查不冒充官方 invalid 判分；官方汇总与本地诊断分别报告。

**继续与停止。** 离线检查只允许进入实验。检索覆盖不达门槛时最多一次有界修正，仍不足则停止扩库；真实小批净收益不为正、出现明显错误迁移或资源超限时不晋级。正结果只允许扩大验证，不能直接保证上线收益。unknown 或争议足以改变净收益方向时先复核，不删题、不将未知算对、不反复重跑挑最好一次。

**后续验证。** 使用已有 Q2 工作流记录新代码、数据、配置和重复证据，不复用旧未传 False 的响应作为新基线。针对经过筛选的少量候选另行冻结可负担的重复和留出规模；未执行完整协议时标记探索性结果，不声称统计稳定。正式机会验证已准备好的候选，不阻塞另一条线的离线开发。

## 8. 工程交付、回退与范围限制

每项实际改动独立开关、定向提交，默认关闭直到有足够证据；记录启用矩阵、代码/语料指纹和验收结果。必要检查包括解析/条件反例、支持范围之外的 unknown、资源限制、入口加载、外部同名模块污染以及默认行为对照。真实运行候选继续执行 Python 3.10/3.12 完整检查，保持现有 60 秒门禁，不为新代码放松历史保护。

首批不增加候选数量、不改变思考协议、不抬高统一预算，不做大规模包结构迁移、不引入运行时联网下载或跨题状态。新增模块与资源采用明确的项目命名和相对加载方式；接入前更新唯一架构文档，核验实际提交资源齐全。库内文本和模型生成的计算输入都作为数据处理。

失败时关闭对应开关，保留失败结果和日志；不可用相同标签覆盖旧实验。正式版本用已验证的具体提交与配置确定，当前 main 在有明确发布安排前保持不动。

审核通过后预期交付：第一批可复现的离线实现与覆盖报告、各策略独立实验计划、后续获授权实验的完整回执、明确的保留/关闭决策，以及最终候选的版本和验收清单。当前实际交付仅为本审核稿及两份分项文档的入口更新。
