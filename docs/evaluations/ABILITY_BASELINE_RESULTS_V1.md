# P0 公开能力基线执行结果（v1）

## 结论

冻结旧版 `831b94f1f0e2e57a4cf93e5c4b3f588c89f0d5cb` 已在固定 PutnamBench 120 题公开基准上完成 3 次真实 35B API 运行，共 360 个题目运行。可靠性门禁通过：请求级截断点估计 2.55%，单侧 95% Wilson 上界 3.06%，候选生成截断率 3.83%，恢复覆盖率 100%，`invalid=0`，截断残句泄漏为 0。

本结果尚不包含数学正确率。证明题和开放表达题必须盲审；在候选版本尚未生成时先单独判旧版，会削弱 A/B 对称性。因此当前 360 个结果全部保留为 `unknown`，不能解读为 0% 正确率，也不能据此声称解题能力提升。

`recovery` 和 `emergency` 的阶段比例较高，但样本小且属于截断后的兜底请求，不能用它们增加总请求数来稀释候选生成率。正式门禁同时检查了候选生成自身的比例。主要截断来源仍是 `policy_tool`，三轮合计点估计 4.72%，低于 5%；后续若需要继续压降，应只针对工具候选的提示长度做单变量修改。

## 恢复结果

81 个截断事件全部被状态机处理。其中 69 个短恢复直接成功，12 个短恢复失败或被隔离；这些失败没有进入正常聚合，最终 64 个受影响的题目运行仍全部获得有效答案。该结果满足“截断发生后不能直接判错”的可靠性目标，但不代表兜底答案在数学上正确。

## 下一步

1. 冻结候选版本 manifest，并在相同数据、模型配置、并发和重复次数下运行 3 次。
2. 将旧版和候选版同题输出随机交换 A/B 标签，由评审者盲审 `correct/wrong/unknown/no_answer`。
3. 解盲后运行配对 bootstrap 与单侧精确 McNemar 检验；只有置信区间、显著性、重复方向和候选可靠性门禁同时通过，才能声明公开基准上的能力提升。
4. 最后使用独立命题或私有第三方提供的 100～200 题密封验收集，确认陌生大学竞赛题泛化。

## 已知限制

- 公开题可能出现在预训练语料中。
- API 响应中的实际模型字段没有持久化到旧版 trace；产物只保存了配置模型名。若声明需要响应级模型身份，应补充脱敏记录并重跑所需版本。
- 原始题面、响应、盲审包和逐题报告位于 Git 忽略的 `outputs/ability_baseline_v1/`，仓库只保存协议、哈希和匿名汇总。
