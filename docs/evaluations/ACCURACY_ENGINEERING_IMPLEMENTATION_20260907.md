## 4. 下次实验可复用的控制能力

`create()` 要求新目录及显式的模型、代码/配置/输入摘要与三项总限额；封存计划同时绑定控制器源码和等待参数，后续检测漂移。`run_controlled()` 接入现有 Q1 冻结计划并验证身份；不完整运行保留 `interrupted`，不伪造完整 Q2 槽位。原 Q2 的真实证据、完整矩阵和晋级要求继续适用。

排队、准入和暂停使用同一跨进程文件锁。暂停回执给出最后已准入编号、在途编号和未发送队列；暂停后不能准入下一请求。已准入的请求可能在暂停确认后进入/完成 I/O，按在途请求处理。结果先暂存，完成费用与状态提交后才对 controller 可见，避免回执发布与下一题的竞态。

请求数、请求输出 token 上限与派发截止时间在发送前检查。请求输出 token 是请求体上限之和，不是输入 token 或真实货币费用上限。每次 HTTP 只发送一次、无重试、无重定向。默认连接/读取等待为 10/300 秒；网络子进程默认等待 345 秒，终止收尾最多另加 4 秒，控制器默认等待 350 秒。即使服务器持续传输导致读取超时不触发，本地子进程也有退出边界。关闭本地 I/O 不证明服务端取消计费，缺回执请求的费用继续记为未知。

观测保存正文空白与字段存在/类型/长度、实际 model、finish_reason、usage 和错误类别；不把隐藏推理正文当答案，不记录鉴权头、key、提供方请求 ID 或异常原文。失败或回执不确定即全局停止，保留已完成题和未知用量。

CLI 仅支持 `status`/`pause`，不会启动网络。未来真实运行须采用新计划与新目录，由单独授权的网络 worker 显式构造 `make_http_sender()`；本次测试只使用假传输和本地无网络子进程。该工具验证的是本地控制协议，不是正式平台的取消契约，也不是网络稳定性实测。
