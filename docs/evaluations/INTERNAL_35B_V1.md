# Intern-S2-Preview-35B 内部大规模评测（v1）

## 结论

`Intern-S2-Preview-35B` 在本项目生成的 396 题内部合成集上，经单人逐项复核后为 **396/396**。这个结果说明当前 Agent 能稳定完成这批公式型题目，也说明该基准已经饱和；它**不是**大学数学竞赛实际正确率、官方成绩或与预训练语料独立的能力估计。

原始保守自动判分为 376 题 `correct`、11 题 `wrong`、9 题 `unknown`。保存 trace 后复核全部 20 个非自动正确项，均确认数学结论正确：11 个 `wrong` 和 9 个 `unknown` 都来自答案表现形式。复核由本项目单人完成，未采用双人盲审，因此单独保留“自动分数”和“复核分数”，不把两者混写。

## 20 个自动评分异常的根因

| 类别 | 数量 | 示例性质 | 处理 |
| --- | ---: | --- | --- |
| 特征根标签或顺序 | 5 | `m = 4, 7` 对 `4,7` | 复核正确；输出层移除限定标签，多解仍按无序集合判定 |
| `πi` 隐式乘法 | 4 | `16pii` 对 `16*pi*i` | 复核正确；输出层补显式乘号 |
| 角度符号 | 4 | `160°` 对 `160` | 复核正确；数值归一化忽略单位符号 |
| 语义布尔回答 | 3 | “一致收敛”回答“是否一致收敛” | 复核正确；仍保留人工复核，不做脱离题面的激进文本判定 |
| 精确值加近似值 | 2 | `4480/19683 ≈ 0.2276` | 复核正确；最终答案行优先保留精确部分 |
| 仅给小数近似 | 2 | `0.1353` 对 `exp(-2)` | 复核正确；提示词要求已有精确形式时不得只写近似值 |

格式修复只影响答案归一化和提示要求，没有改变模型、候选数、温度、thinking mode、工具轮数或聚合策略。旧运行不会被改写，原始自动分数仍按冻结 commit 保存。

## 为什么仍未测出“实际正确率”

这次测试解决了“36 题太少”的问题，但没有解决另外两个更关键的问题：

1. **难度没有被独立校准。** 396 题中 284 题题面少于 40 个字符，309 个参考答案不超过 3 个字符；大量题目可直接代公式或做短计算，缺少证明、反例、参数分类和长链推导。
2. **题目独立性不足。** 396 题只有 108 个生成模板，且题目与答案均由项目方生成。它们没有进入项目 prompt 或公开样例，但无法证明与模型预训练语料在知识或模板层面独立。
3. **只有一次随机运行。** 不能估计采样方差，也没有与旧版本在同一盲测集上做配对比较。
4. **复核不是双盲。** 单人可依据 trace 纠正格式误判，但不足以支撑正式竞赛成绩声明。

因此这次结果应解释为：**当前内部公式型压力集已饱和，继续生成更多同模板变体的收益很低。** 下一步应把预算放到第三方私有题、人工新命题和证明型题上，而不是继续扩大相似合成题数量。

## 下一轮建议

建立一套 100～200 题的私有挑战集作为下一阶段，比立即再生成数百道公式题更有信息量：

- 由至少两名独立命题或复核者提供题目，题面在冻结前不进入仓库、prompt 或错误模式库；
- 重点覆盖证明、反例、参数分类、多知识点组合和长程推导，每题记录难度依据及评分 rubric；
- 先冻结题目、模型、配置和 commit，再让原版与现版使用相同题目、相同调用预算和相同重试规则；
- 每题做配对裁决，报告原版独对、现版独对、共同正确、共同错误，并使用 McNemar 检验；
- 随机策略至少重复 3 次，同时报告自动分、盲审分、格式失败、请求量、token、延迟和运行错误。

只有这一步完成后，才能给出比“内部合成集 100%”更接近实际大学竞赛场景的正确率区间。
