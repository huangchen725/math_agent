## 回归窗口与根因

2026-08-29 的同一隐藏集、同一平台环境在 `350a267` 上产生 1,082 次真实请求并得到 23/112；本轮 `70ac53f` 在 42 秒内完成 112 条错误记录且没有一次请求。因此回归窗口位于 `350a267..70ac53f`，并集中在 S2 模型入口重构，而不是数学策略或网络服务。

官方 baseline 只保证注入客户端的公开接口：

```python
client.chat(messages=..., temperature=..., max_tokens=...)
```

正式 client 可以含资源统计、限流和安全控制等额外实现，但参赛代码不得依赖私有字段或方法。S2 的 `ModelGateway` 却通过名字探测任意 `chat_with_metadata`，只要方法存在就优先调用，并强制其返回项目自定义的二元组。若官方 client 恰好有同名内部扩展但签名或返回契约不同，请求会在进入公开 `chat()` 前同步失败。候选、紧急答案和全局 fallback 都经过同一网关，因而每题最终都收敛为无效输出。

脱敏日志没有逐题异常正文，无法读取官方私有方法的精确返回值；但以下证据共同把该问题确定为本轮最高置信度根因：

1. 旧版只调用公开 `chat()`，同平台完成 1,082 次请求；
2. 新版唯一模型入口新增了未声明的私有方法探测；
3. 使用“公开 `chat()` 正常、同名私有方法返回不同结构”的官方形态 fake client，可以稳定复现请求前 `TypeError`；
4. 删除隐式探测、要求项目自有客户端显式声明原子元数据协议后，同一复现正常调用公开 `chat()`。

## 修复边界

- 外部注入客户端始终只走竞赛公开保证的 `chat()`。
- 只有项目自有 `InternChatClient` 显式声明 `math-agent.atomic-metadata.v1` 时，网关才调用 `chat_with_metadata()`。
- 没有恢复 `get_last_response_meta()`、ContextVar 或其它隐式上下文。
- 模型、三候选、温度、thinking mode、token 上限、工具轮数、验证、恢复和聚合规则均未改变。
- 平台 client 只提供公开文本接口时，Agent 内部无法取得其私有 usage/`finish_reason`；平台汇总仍可独立统计。这一限制必须与“官方运行可用”分开记录，不能再用未公开接口换取内部观测。

## 离线验证

- 网关级回归覆盖：注入客户端同时具有可用 `chat()` 和不兼容同名私有方法时，只调用公开接口。
- Agent 级回归覆盖：完整 `ReasoningAgent.solve()` 在相同客户端形态下完成候选与 verifier 两次公开调用，并输出唯一末行答案。
- 完整质量门禁 20/20 通过：175 项测试通过，语句覆盖率 76.57%，Ruff、compileall、Bandit、Python 3.10/Linux 锁闭包、`pip check`、三套锁漏洞审计、敏感信息、文档链接和所有非模型入口均通过。
- 验证过程中没有调用真实模型 API。

门禁首次运行还发现跨权限遗留的共享 pytest 临时目录不可访问，以及漏洞审计默认用户缓存不可写。质量入口已改为每个进程和检查使用独立项目内临时子目录，漏洞缓存也固定到忽略的 `.quality/` 内；这两项属于验证基础设施修复，不改变 Agent 运行策略。
