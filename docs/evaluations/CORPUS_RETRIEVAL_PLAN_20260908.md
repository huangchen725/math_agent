## 最小实验：先回答命中是否有用

1. **语料样本。** 首批只做一个领域，目标 100–200 条经过核对的定理/已解例题卡。每条包含来源、版本、许可、章节/题号、完整条件、解法、结论及文本指纹。保留公式和条件，禁止把语料中的指令当成 Agent 指令。此规模是建议上限，不是已经入库的数量。
2. **零 API 检索检查。** CPU 本地只读索引，先用词项/BM25 或字符检索，配中英文数学术语表。区分完整同题匹配与相似解法检索。先审查 12–24 个公开查询的 top-2 是否提供可用方法，以及 20 个改条件反例是否被误认同题。查询不得带评估参考答案；反例不能用来计算一般解题正确率。
3. **匹配规则。** 同题键最多规范化无意义空白与明确等价的排版，必须保留正负号、数值、定义域、量词、矩阵维数和边界条件。已有去重工具的“模板相同”不等于答案相同，其去数字模板不能直接用作查表键。改数值、实数改复数、存在改任意的近邻题必须退出直接匹配。
4. **辅助求解候选。** 若检索检查有价值，再准备默认关闭的独立检索开关：只在一个候选的生成上下文添加至多两条相关参考，不增加模型调用；无可靠命中则保留原路径。检索文本设置字符/字节硬界限，起步总量不超过 6000 字符；实际输入 token 另记，不将字符上限冒充 token 上限。保留 `thinking_mode=False`、8192 输出上限、候选数、温度及选择流程。B1/B2 在配对两侧保持相同且先关闭。
5. **小批真实初筛另行冻结。** 检索通过后，先计划 6 道独立开发题、每题基线/检索各一次的单候选生成，共 12 次模型请求，无自动重试、无整套 Agent 展开，输出上界 98,304 token，输入成本另记。真实执行仍按项目既有额度流程处理；本次请求数为 0。这个小样本只用于发现明显帮助或误导，不证明稳定收益。通过后再用既有工作流检验端到端选择是否保留收益，并单独安排留出验证。

正式运行环境不依赖联网搜索、在线向量库、运行时下载或跨题缓存。相对资源路径以入口文件位置解析；真正接入正式运行时前仍需核验资源装载与包大小，不能把“本地索引可读”视作平台验收。具体模块改动在实施时更新唯一架构文档，本提案不宣称已接入。

## 计分与停止条件

分别报告三组结果：库内同题的记忆命中率、改条件题的误匹配率、来源/题族分离题的最终正确率。第一组可以说明查表能力，但不能混入第三组声称推理提升。既有留出标签不参与选库、阈值调优或提示构造。

离线继续条件：所有条目来源许可完整；20 个已审查反例中同题误匹配为 0；独立开发查询至少一半有经审查可用的 top-2 参考。该门槛是本次提议的投入筛选标准，0/20 不证明总体误匹配为 0。若不通过，优先检查跨语言和公式检索，最多一次有界调整；仍无覆盖就暂停扩库。

真实初筛记录每题“原错新对、原对新错、两者皆错、unknown”、答案完整性、输入/输出 token、耗时与请求数。净收益不为正、出现明显的错误迁移或成本不可接受时不晋级；不通过删题、反复重跑或把 unknown 判为正确制造收益。一次正结果只支持扩大验证，不保证隐藏集分数。

查表上限取决于覆盖。仅作示意：假设未命中题仍保持 25/112 的正确率，命中题全部正确，要达到 90%，需要约 87.1% 的题被正确命中。实际命中率和误匹配损失均未知；因此堆入大量文本不能自动推出接近满分。
