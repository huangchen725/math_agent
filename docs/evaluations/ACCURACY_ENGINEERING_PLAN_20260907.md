# 正确率改进工程计划：审查稿

状态：供用户审查，尚未实施本计划。真实 API 实验保持暂停，不自动续跑、晋级、推送或提交。本文描述拟议工作，不替代 `ARCHITECTURE.md` 的当前架构事实。

## 依据与目标

依据 [已暂停实测报告](ACCURACY_PILOT_20260907.md)：基线 72/72 完成，compact_routing 11/72 完成。83 份完成答案和 v3 的 494 份请求回执已保存；第 12 道对照题的部分请求只计成本，不计完成题。基线单次 assistant 数学审核为 56 correct、2 wrong、12 no_answer、2 unknown；已有 11 道配对结果一致，尚不能判断简化领域提示的整体收益。

工程目标按顺序为：减少完整正确答案的交付损失；降低无效恢复与校验成本；用有上限的小实验筛选数学策略。不得把格式修复、可提取候选增多、单次 assistant 审核或小样本变化直接称作正式正确率提升。

本计划不要求先跑完剩余 61 道对照题。保留原研究的未完成状态；代码或配置改变后另建身份绑定的实验，不续写旧冻结研究。

## A 组：已有反例，可先完成零 API 工程验收

### A1 完整答案提取与格式修复（最高优先级）

- 位置：`user_agent.py` 的 `_extract_answer`、`_valid_answer_body`、`_build_response`，以及对应回归测试。若涉及数学记号归一化，单独审查 `answer_equivalence.py` 的变化。
- 实施：在原有长度限制内，识别明确的最终答案标题、标题后的编号列表及两种粗体标记；把一个完整答案块按原次序转换为唯一最终行，保留小题编号、定义域、单位、绝对值、精确表达式。
- 边界：仅扩展有明确标记和边界的格式。最后一个答案标记为空或不完整时，不退回较早答案；最终块存在时，不让较早 boxed 中间值抢占。无法确认边界、超限或存在显式截断时继续拒绝。不能把任意推导末行当答案，也不能通过截取前 2048 字符伪装完整。
- 验收：真实第 8、13、38、48 题的相关响应及通用变形均进入回归；覆盖多小题不遗漏、标题换行、无冒号标题、两种粗体边界、较早 boxed、最后空标题。正常 `x**2` 保留幂语义，`**最终答案：** 7` 不再变为 `^ 7`；有意义的空白/Markdown 变形保持答案等价，重复格式化幂等。
- 交付：固定反例、有限输入性质检查、原/新提取差异表。只报告答案交付变化，不重新声称这些原始运行已答对。

### A2 补答传递保持完整性信息（最高优先级）

- 位置：`_quick_fallback`、`_solve_tools`、可选 `recover_plain` 分支及 `_answer_for_aggregation`。
- 实施：明确“原始模型响应”和“已验证答案体”的区别，在现有内部边界内保留合格补答的最终标记/状态，避免裸符号答案被第二次提取丢弃。优先最小局部修复，不借此重构整个候选架构。
- 验收：数字 `7`、符号 `sqrt(2)`、真实 `tan^2(alpha)` 恢复都能正确传递；覆盖工具候选、可选普通候选恢复、全部失败后的最终兜底。空响应、残句、异常及 length 响应仍不可进入聚合；任意一次转换不得洗掉未完成状态。
- 交付：与 A1 分开的代码差异和状态转换测试，证明有效恢复不丢失、无效恢复不复活。

### A3 既有响应回放与故障归类（最高优先级，支撑 A1/A2）

- 位置：离线 `evaluation/` 与测试；原始材料继续留在受控 `outputs/`，提交的测试使用通用最小反例。
- 实施：对 83 个完成 checkpoint 和相关原始响应建立只读清单，绑定源码、配置、题集、响应摘要与阶段；区分生成错误、完整答案提取失败、恢复丢失、校验无结论、选择错误、最终条件遗漏、传输异常等，允许同一题有多个原因。
- 验收：回放零 API、无参考答案进入求解请求、原文件摘要不变。真实响应只用于其匹配的阶段/输入；如果修复导致后续请求消息改变，回放停在分叉处并标记缺少对应响应，不能按旧顺序硬塞响应。模块级修复可以用同一旧响应比较，提示改变后的新输出必须另做真实实验。
- 交付：每项修复的影响清单，包括已恢复、仍未恢复、原已合格但发生变化、无法继续回放；不制造虚假的新整套正确率。

### A4 小批实验控制与观测（下次联网前完成）

- 位置：本地专用执行器及测试，位于正式导入闭包之外。复用现有 Q1/Q2 记录工具；旧 v3 辅助脚本与凭证保持原样。
- 实施：补齐总耗时上限、请求上限、请求输出 token 上限和暂停协议；派发方与网络方共享停止状态，每次发送前检查。暂停确认记录最后已派发编号，确认后不再派发；在途响应单独收尾、记账，不将未完成题标成完成。并发请求控制仍默认串行，不靠加并发解决耗时。
- 观测：记录响应正文是否为空、必要字段是否存在/长度、实际 model、finish_reason、usage 和错误类别，保留有界本地证据。缺失字段不推测；reasoning_content 不自动充作最终答案；不输出鉴权头和密钥，不扩充正式公开 trace。
- 验收：用假服务验证暂停与派发竞态、总时长到点、在途正常/失败返回、进程退出、预算计数及未知用量；没有第 N+1 次偷偷发送，无自动重试/恢复，无漏记失败或在途成本。日志采集不改变传给 Agent 的响应。
- 交付：可暂停、可限时、可审计的最小实验控制改进，不新增常驻服务或调度系统。

### A5 判分与参考争议整理（与 A1/A2 并行推进的独立工作）

- 位置：离线审核报告、现有评分/审核工具；不进入运行时选答案链路。
- 实施：整理已证实的第 28、66 题参考错误，以及数域、误差容限、最少项数等争议；准备明确的数学依据和匿名复核材料。先解决已知问题，不扩建通用语义判分器。
- 验收：冻结原标签、旧分数和旧研究不变；若采用参考修订，生成新版本并对两组保存输出按同一口径重新评分，无需为改标签重新调用模型。无法证明的等价保留 unknown，最终行与全文推理的判定差异明确记录。
- 交付：自动评分、单次 assistant 数学诊断、独立复核三种证据分列。基线自动评分的 60 unknown 不能被解释为 60 错题或 0% 模型正确率。

## B 组：可工程实现，效果须小批实测

以下先写独立开关和验收方案，保持默认行为不动。每项使用同一已修复的工程基线单独比较；不同时改变提示、候选数、温度、预算或聚合。A 组修复累积版本按工程修复声明，不冒充某项提示的单变量收益。

### B1 提示与真实可用工具一致（首个策略候选）

- 实施：在明确未配置本地工具适配器的路径中，系统提示和用户提示统一要求纯推理，消除“请调用工具”及等待外部工具反馈的要求；有显式适配器的本地工具路径仍使用其对应提示。保留原领域知识内容，领域提示长度作为另一项实验。
- 边界：不探测注入 client 的类型、属性或签名；不增加 tools、thinking_mode、stream、n 等参数。工具调用文字不视为真实执行，也不因为全文出现工具字样就否定一个有效最终答案。
- 验收：无工具路径所有候选来源不再互相矛盾地要求工具调用；小批记录工具文本停滞、完整答案率、最终正确题数及成本。纯粹没有工具文本不等于答对。

### B2 短补答提示与预算（第二个策略候选）

- 证据：基线 91 次 512 token 恢复中 82 次 length。
- 实施顺序：先为补答提供一致的简短系统/用户指令，保留 512 上限单独比较。若仍不能完成，再独立比较一个预先指定的较大预算档位；不一开始同时改提示和预算。
- 验收：比较合格答案产出率、数学正确性、总成本与最终交付；不得接受截断响应里出现的临时答案，不增加盲目重试。限制全局成本，不能用无限加长掩盖无效补答。

### B3 校验是否值得调用（第三个策略候选）

- 证据：基线 121 次校验中 72 次 length/unknown，48 次 pass、1 次 fail；现有结果不能证明校验有净收益。
- 实施顺序：先按已有正确/错误候选检查当前校验输入与判决，再分别比较简洁校验指令、关闭校验或单独调整预算；每次只选一项。critic 与 reflection 也必须分别消融，不能一起关闭后声称知道各自作用。
- 验收：不仅统计判决是否完整，还统计错答案被放行、对答案被否定，以及最后实际选对/选错的变化。unknown 不投票、不触发纠错。阶段判别试验的答案标签只用于事后评分，不能当成整题正确率。

## C 组：根据诊断再决定，暂不同时铺开

- **最终条件保持**：针对已见的绝对值/定义域遗漏，先评估“最终答案必须保留成立条件”的独立提示；不能通过字符串猜测自动给公式补绝对值。用正负区间和边界反例验收，数学收益需新输出验证。
- **候选多样性与数量**：只有明确存在“所有候选都错”或“正确候选被重复错误压过”的证据后，再选择多样性或数量中的一项。现有 diverse_candidates 同时改变提示和温度，使用前拆分或明确作为组合假设。
- **确定性校验**：优先审查既有有界解析和验证能力，只有完整匹配适用域才给证据；覆盖外保留 unknown。符号例子通过不代表可以启用无界 CAS 或普遍语义判断。
- **简化领域提示**：保留 compact_routing 作为候选，已有 11 题不足以判断有效或无效；优先级排在已证实的交付故障之后。
- 现有路线中的架构阶段 A1（大规模目录/架构迁移）、模型切换和扩大并发不纳入本轮提分包；它与本稿工作包 A1 的答案提取修复是不同编号体系。

## 后续联网筛选提案（本稿不启动）

1. **阶段短试**：B2 或 B3 一次只选一项，用预先冻结的 8 个阶段输入分别跑旧/新两种设置，每组各 8 次、合计最多 16 次真实 HTTP 发送，无重试。先验证输出完成性与判别质量。若沿用 512/1024 阶段上限，请求输出 token 上限分别为 8,192/16,384；预算实验必须重新计算。派发窗口最多 10 分钟。
2. **整题小筛选**：阶段短试通过后，预先冻结六领域各 1 题，基线/候选各一次，共 12 次 solve；默认每题至多 16 请求，真实请求上限 192，保守请求输出上限 1,572,864 token，派发窗口最多 60 分钟。历史每题平均耗时只作估计，不保证完成；样本不是盲测或稳定收益证据。按题交替两组顺序并记录，减少顺序偏差。
3. **停止与结论**：任一上限先到就停止新派发，当前在途请求最多按 350 秒本地外层窗口收尾，报告另外计入收尾时间。任何不确定传输/协议失败立即停止，未知用量不填零；超时未完成保留为未完成结果，不删除或补跑来美化结果。输入 token 与货币费用仍需按实际回执及已确认价格核算，不承诺固定费用。
4. **扩量条件**：阶段短试至少解决一个预登记故障类型，且不新增已确认的错答放行或正确答案丢失，才进入整题小筛选。整题小筛选建议门槛为：六题至少净增 1 道确认正确；或确认正确题数相同、无新增待定/未交付且实际 token 减少至少 20%。任何原正确题的明确回归先定位，不用净增数掩盖。未达到则保留为无收益/待定，不自动扩量。上述数字是拟议的工程初筛门槛，不是统计显著性或完整 Q2 晋级标准；题集过小无法证明稳定收益，正式兼容与完整 Q2 晋级仍按原证据要求执行。
