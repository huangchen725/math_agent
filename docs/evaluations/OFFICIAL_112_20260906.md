## 代码诊断：事实与假设分开

以下静态诊断绑定 `git show c009929:user_agent.py` 及 `git diff ba63ac0 c009929 -- user_agent.py`，默认配置不代表已经拿到正式实例配置回执。

1. **请求语义确有变化。** R0 向生成、验证、批评、反思和兜底请求传 `thinking_mode=False`；本次版本为了采用公开三参数协议，已不再传该参数。配置中的 False 字段仍存在但不能关闭服务端思考。接口收缩可能改变实际推理行为，不能视为已经证明行为等价的纯工程修改。
2. **输出预算仍沿用旧值。** 生成和反思 8192、验证/批评 1024、兜底 512，单题软期限 600 秒。若服务端开始长思考，短请求可能在输出结论前耗尽预算；生成耗时增加还可能使后续请求触发软期限。日志没有阶段明细，无法给这些原因分配题数。
3. **旧版恢复存在确定的残句出口。** `_extract_answer` 无标记时取最后一行前 200 字；`_quick_fallback` 还有 `ans or resp.strip()[:200]`。`_is_likely_truncated` 主要拒绝无答案标记且长度达到 3000 的长文本，短残句可能通过。这是代码事实；无法仅凭汇总确认本次有多少 invalid 经由该路径产生。
4. **旧版验证存在误判风险。** 没有识别到正确标签的验证文本会落到否定票；验证本身截断不能作为候选错误的可靠证据。1024-token 验证请求是否占多数截断，日志无法回答。
5. **当前修复有范围限制。** `9126c04` 已阻止恢复残句进入答案，`6d42d2c` 提供默认关闭的 Q1 校准等实验开关。两者均未出现在本次评测；默认 512/1024/8192 配置和三参数调用仍在。拒绝残句能改善完整性约束，却不自动增加可用答案，甚至可能将假答案转为“未解出”。必须实测完成率与正确率。

2026-09-06 只读核验的[书生官方 Chat 文档](https://internlm.intern-ai.org.cn/doc/docs/Chat/)明确说明 397B 默认开启深度思考，普通 API 可用 `thinking_mode` 控制。因此“未传关闭参数 + 服务端长思考 + 沿用短预算”是优先验证的解释，**不是已经证实的本批次唯一根因**。普通 HTTP API 支持该参数，不证明竞赛注入 client 接受第四个关键字；也不证明本次实际调用的是 397B。动态文档没有不可变版本，不能回填成运行时回执。
