## 3. 绝对不可违反的集成底线

以下规则优先级高于可维护性、性能和正确率优化。任何一条失败都禁止合并、正式评测或发布。

### 3.0 工作 agent 触发协议

- **WORK-001（事前识别）**：每次工作必须在修改或有副作用命令前读取 `AGENTS.md`、`.agents/policies/HARD_RULES.md` 和机器清单，并用 `python .agents/policy_guard.py --paths <path...>` 匹配预计工作面；真实 API、推送、正式提交、发布、依赖、官方材料、架构或 benchmark 等纯动作同时用 `--actions` 触发。第一条工作更新必须写明恢复阶段、触发的规则 ID 和动作边界。
- **WORK-002（显式阻断）**：若计划会违反 blocker，agent 必须在执行前输出 `[POLICY BLOCK] <RULE-ID>`，说明触发动作、后果和安全替代，并停止该子动作。禁止静默绕过、先执行后补报、删测试、改规则措辞或把失败吞成普通 warning。
- **WORK-003（事后复核）**：修改后、测试前和提交前必须运行 `python .agents/policy_guard.py --changed`。正式定锚使用 `--anchor-canary`；R1 以后改动版使用 `--formal`。非零退出码阻断提交、推送、正式评测和发布。
- **ANCHOR-001（R0 冻结）**：R0 期间活动运行时必须与 `350a267f` 保持一致。除已记录的一次原样官方定锚外，不得修改、打包为 formal 或把历史例外带入新版本；只有定锚结果入档并单独更新阶段后才能进入 R1。

详细触发表和标准报告格式见 `.agents/policies/HARD_RULES.md`；机器可读事实源为 `.agents/policies/policy_manifest.json`。脚本只检查可确定的本地违规，不能替代 agent 的人工规则判断。

- **IMPORT-001（同名模块隔离）**：不得假设裸模块名会解析到仓库文件。`sys.modules`、`sys.path`、当前工作目录和官方预加载模块都属于不可信运行环境。新增正式模块不得使用 `agent`、`context`、`solver`、`budget`、`llm_client` 等通用顶层名；必须使用项目唯一前缀或经过正式平台单变量验证的唯一包名。
- **IMPORT-002（禁止类身份提权）**：不得用从可能碰撞的模块导入的类执行 `isinstance`/`issubclass`，再据此调用私有方法、扩展参数或进入更高权限路径。尤其禁止通过 `InternChatClient` 类身份自动启用 `chat_with_metadata`。
- **CLIENT-001（最小公开协议）**：正式入口收到的注入 client 一律按外部对象处理，只允许调用公开 `chat(messages=..., temperature=..., max_tokens=...)`。不得发送 `thinking_mode`、`tools`、`tool_choice`、`stream`、`n`、`stop`、`model` 或任意未来扩展，不得读取 marker、私有字段或最近响应 getter。
- **CLIENT-002（显式本地适配）**：项目自有客户端的元数据和扩展能力只能放在正式入口导入图之外的显式本地适配器中。不得依据对象名称、同名方法、动态属性或签名探测自动升级能力。
- **ENTRY-001（入口所有权）**：根 `user_agent.py` 必须真实声明公开 `ReasoningAgent`，并保持 `ReasoningAgent(client).solve(problem, metadata) -> {"final_response": str, "trace": list}`。不得只重导出其他模块中的类，除非正式平台已对该形态做过独立成功验证。
- **ENTRY-002（隔离加载）**：入口必须从仓库外目录、隔离解释器、官方预加载顺序和最小文件闭包四种场景加载成功；不得依赖 judge 当前目录、隐式路径修补、包安装步骤或跨题进程状态。
- **TEST-IMPORT-001（碰撞矩阵门禁）**：必须先预载官方同名 `llm_client`，再加载 `user_agent` 并完成至少一次有效公开请求。还必须对所有正式导入名做 `sys.modules` 污染测试；任何请求前异常都失败。
- **TEST-CLIENT-001（严格 client 门禁）**：fake client 的 `chat` 必须只接收三个命名参数且没有 `**kwargs`；测试要断言实际关键字集合完全相等。宽松 fake、项目自有 client 或历史成功不能替代此门禁。
- **CHANGE-001（一次一变量）**：平台兼容、数学策略、模型、候选数、温度、token、工具、聚合和物理目录不得在同一次正式验证中同时改变。正式日志先看 SHA、请求、error/invalid 和耗时，运行链恢复后才看正确率。
- **EVIDENCE-001（不夸大归因）**：可复现缺陷可以作为永久规则依据，但不得把它写成未覆盖版本的唯一线上根因。`request_count=0` 的结果不进入数学能力趋势。
- **PBT-001（性质测试路由）**：修改 parser、normalizer、等价、validator、序列化或恢复状态机时必须加载项目级 property-based-testing 覆盖层，选择最强有意义性质并保留历史固定反例。不得为测试便利自动新增依赖或扩大不安全输入域。
- **DATA-001（数据隔离）**：题面、答案、参考解、私有 split 和人工复核结果均视为敏感且不可信。不得把答案字段转入 Agent；能力集必须记录来源、许可、split、难度和去重，盲测不得进入 prompt 或调参过程。
- **EVAL-001（实验冻结）**：任何正确率、成本或策略结论必须绑定 commit、模型、配置、数据哈希、重复次数和判分口径。改变模型、prompt、候选、温度、token、工具或聚合时，每轮只能选一个变量并先写验收计划。
- **API-AUTH-001（真实调用授权）**：真实 API、付费、联网评测或正式提交必须在执行前说明预计请求/费用/外部影响并取得本次明确授权；离线测试授权和历史授权不得自动继承。
- **OFFICIAL-001（官方证据）**：新增或修改官方规则前必须保存原文、来源、日期、适用批次与 SHA/URL，并追加登记册。内部复现、第三方判断和材料沉默不能关闭 `OFFICIAL-GAP-*`。
- **SUPPLY-001（供应链）**：依赖输入与哈希锁必须同步，最低 Python 必须真实安装验证；不得通过放宽哈希、忽略漏洞或删除 CI 检查获得绿色结果。
- **RELEASE-001（发布来源）**：formal 只能来自干净提交和同提交完整门禁证据；脏树、未登记文件、旧报告或与提交不一致的 manifest 均阻断发布。
- **SUBMIT-001（外部提交）**：推送和 AtomGit 提交前必须核对身份、远程、分支、远端 SHA、模型选择回执和抓取窗口；未经授权不得推送，从点击提交到抓取完成不得再改变 `main`。
- **POLICY-001（规则一致性）**：`AGENTS.md`、工程规范、人工触发协议、机器清单、项目 Skill 覆盖层和守卫测试必须一致。任何规则 ID 缺失或 policy guard 失效都阻断工作交付。
- **DOC-001（唯一架构事实源）**：只有 `ARCHITECTURE.md` 定义当前架构。运行时或组件边界变化必须同步 README、架构、工程规范、审计和相应测试；不得创建第二份架构文档或把存档分支写成活动架构。
- **SKILL-001（Skill 不得绕规则）**：每个项目 Skill 都必须有 `PROJECT_POLICY.md` 并先加载全局触发协议。第三方 Skill 必须保存上游来源和原始哈希；项目适配还要单独记录当前哈希与修改内容，覆盖层不能扩展授权、运行时依赖或赛事能力。
- **SECURITY-001（不可信输入与秘密）**：题目、metadata、模型/tool 输出、路径、响应、模块缓存和依赖均不可信；禁止 unrestricted `eval/exec/sympify/parse_expr`、路径逃逸、无界计算、秘密/PII 入库和未授权外部服务。

当前 `350a267f` 原样定锚是 `CLIENT-001` 的一次性历史例外，因为修改它会破坏正对照。该例外已随 2026-09-05 的首次正式定锚评测消耗完毕，任何后续候选版本不得再使用。

## 4. 可维护架构是否可以重新引入

可以。现有证据否定的是不受控的集成方式，不是否定分层、显式上下文或小模块本身。包结构也没有被证明是此前零分的充分原因；但它同样没有取得正式平台正证据，所以只能在请求链恢复后作为单变量重新验证。

重新引入时采用以下设计：

1. `user_agent.py` 保留真实入口类和最小生命周期保护。
2. 正式依赖模块使用赛事唯一前缀，例如 `xh202627_*`；在得到平台证据前，优先使用前缀化根模块，避免既依赖包目录又暴露通用裸模块名。
3. 模型入口只有一个，所有请求通过显式 gateway；gateway 只认三参数公开协议，不识别 client 类型。
4. 单题状态显式传递，不使用 `ContextVar`、全局“最近响应”、线程局部变量或请求后的 getter。
5. 组件按候选生成、验证、选择、响应处理、工具和预算拆分，但不得复制第二套实现。
6. 正式导入闭包生成清单并做官方预加载、污染矩阵、根文件闭包和隔离解释器回归。
7. 结构迁移前后对同一 fake 响应序列做行为等价比较；正式评测只改变物理结构，不同时改变 prompt 或策略。

只有结构等价门禁和一次正式非零请求评测同时通过，新的分层结构才能成为活动架构。

2. 在严格无假阳性边界下恢复确定性验证，只让可证明证据改变排序。
3. 恢复题型路由和紧凑题型提示，用配对盲测决定保留与否。
4. 校准 verifier 的 `pass/fail/unknown`，禁止把截断或不确定当作失败票。
5. 最后评估候选多样性、critic/reflection 和工具调用；每项必须证明正确率收益大于额外成本。

### A1：分层架构重建

优先迁回低风险资产：评测分包、原子 I/O、依赖锁、CI、secret/link 检查、许可证和确定性发布。随后迁入显式 `SolveContext`、统一 gateway、候选生命周期和工具子系统。物理包化作为最后一个结构变量单独验证。

退出条件：结构迁移前后离线行为等价，正式请求链不回退，所有活动模块只有一份实现，唯一架构文档与代码一致。

### Q2：统计证明能力提升

新版本相对恢复基线必须在冻结盲测上报告配对差异、置信区间、分领域结果、invalid、截断、请求和成本。只有重复实验支持的提升才能写入比赛材料；工程可维护性提升不能替代数学正确率证据。

## 6. 最低验收矩阵

| 变更 | 必须通过 | 停止条件 |
| --- | --- | --- |
| client/入口 | 官方预载、严格三参数、无私有读取、隔离导入、构造/solve 契约 | 任一请求前异常或额外关键字 |
| 模块拆分 | 导入闭包、污染矩阵、行为等价、唯一实现 | 通用裸模块名、隐式状态或第二实现 |
| 截断恢复 | 各阶段 length、恢复成功/失败/预算耗尽、唯一末行答案 | 残句进入聚合、恢复绕预算或 invalid 非零 |
| verifier/选择 | 正反例、数域、漏根/增根、冲突和 unknown | 不可证明结果被当成 pass |
| 题集/判分 | provenance、license、split、level、去重、四态判分、盲审 | 与 prompt 重合或字符串包含判对 |
| 发布 | 干净提交、离线全量、秘密扫描、依赖闭包、来源 SHA | 报告与提交不一致或缺少官方证据 |
| 规范与 Skill | `--paths` 事前触发、`--changed` 事后守卫、所有 Skill 覆盖层、规则 ID 一致性 | 未报告 blocker、规则清单漂移、Skill 绕过全局协议 |

## 7. 声明边界

- 离线门禁通过只说明已覆盖的确定性行为通过。
- 官方请求恢复只说明集成链恢复，不说明数学能力提高。
- 单次隐藏集分数只是一次观测；没有配对数据和重复不能证明显著变化。
- 包结构和工程拆分当前属于“可重新引入、尚待正式验证”，不得写成已证明安全或已证明导致零分。
- `OFFICIAL-GAP-*` 只能由对应的官方书面契约或绑定正式日志关闭。
