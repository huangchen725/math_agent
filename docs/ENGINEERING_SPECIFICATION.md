- **必须/不得**：硬规则。违反时停止合并、正式运行或发布。
- **应**：默认要求。偏离时必须在变更记录中说明理由、风险和验证。
- **实验**：不得冒充正式配置、官方成绩或能力结论。
- **已修复**：已有回归测试；删除测试或恢复旧行为视为回归。
- **待验证/未解决**：不得写成已关闭，也不得据此做能力或合规声明。

若不同文件冲突，先按赛事规则失败关闭；架构事实与代码不一致时先停止发布并修正文档或实现，不能选择对当前任务更方便的一份。

## 4. 硬规则目录

### 4.1 赛事与人员行为

- **COMP-001**：正式参赛模型必须为 `intern-s1`。没有归档的主办方书面许可时，网页、baseline README、口头说明和历史 S2 实验均不能放宽该要求。
- **COMP-002**：只允许赛事注入客户端、官方 Intern HTTPS 端点和本地有界工具。不得调用未经允许的外部闭源服务代答。
- **COMP-003**：不得人工逐题选择候选、改写答案、临时改 prompt、切模型或只重跑某一道题。
- **COMP-004**：不得赛后补填结果，不得把人工创建或修改的 checkpoint 记为模型输出。
- **COMP-005**：不得伪造、拼接或原地改写原始日志。重算统计必须生成新文件并记录输入哈希和工具版本。
- **COMP-006**：数据集的 `answer`、`expected_answer`、`reference_answer`、`reference_solution`、`solution` 等判分字段不得进入 Agent metadata、模型消息或求解 trace。
- **COMP-007**：结构化 JSON、必要 trace、非空答案和可复核日志属于正式验收条件；不可解析、缺字段或不可复核可直接判为未通过。
- **COMP-008**：初赛基线保持单 Agent、自然语言理解、规划/求解/解释和 18 领域覆盖；决赛若适用，必须重新核验多 Agent 与交互式 Web/Notebook 展示要求，不能假设初赛实现自动满足决赛。
- **COMP-009**：`COMPETITION_MODE=0` 只表示非提交实验，不能授权第三方端点，也不能使 S2 结果成为正式成绩。
- **COMP-010**：资格红线优先于正确率、展示效果和工程便利；发现不确定授权时必须停止正式运行并请求书面确认。

### 4.2 客户端、模型调用与密钥

- **API-001**：`client` 由调用方注入，外部最低契约只有 `chat(messages=..., **kwargs)`；不得结构探测或调用注入 client 的同名私有扩展。
- **API-002**：只有项目自有 `InternChatClient` 声明 `math-agent.atomic-metadata.v1` 后，`ModelGateway` 才可调用 `chat_with_metadata()`。
- **API-003**：所有普通、工具、验证、批评、反思、恢复和紧急请求必须经过同一 `ModelGateway` 与同一题 `ExecutionBudget`。
- **API-004**：响应文本、tool-call message、`finish_reason`、usage、阶段和请求编号必须在一次返回中原子绑定，不得通过全局、线程局部、ContextVar 或“最近响应”方法拼接。
- **API-005**：赛事端点固定 `stream=False`、`n=1`；不得启用 `stream=True`、`n != 1`，也不得加入未验证兼容性的 `stop` 参数。
- **API-006**：只重试连接错误、超时、明确的限流和临时服务错误；认证、权限、参数校验和其他永久错误不得盲目重试。
- **API-007**：API key 只来自环境变量。代码、测试、trace、日志、文档、质量报告、压缩包和命令输出不得保存或回显密钥/Authorization。
- **API-008**：真实评测首先验证 `request_count > 0`、`success > 0` 和运行耗时合理；请求为 0 的整批结果是入口故障，不得记为数学正确率 0%。

### 4.3 外部接口与输出

- **OUT-001**：必须保持 `ReasoningAgent(client).solve(problem, metadata) -> {"final_response": str, "trace": list}`。
- **OUT-002**：成功响应必须包含且只包含一个非空 `最终答案：...`，并且它位于最后一行；答案体不得含解释句。
- **OUT-003**：模型内部采用答案先行以抵抗截断，外部响应统一为推理在前、唯一答案在末；不得把截断推理残句猜成答案。
- **OUT-004**：只接受显式答案标记或受控裸答案路径；不得恢复“取最后一个非空行”作为答案的旧逻辑。
- **OUT-005**：空答案和 `未解出` 必须作为失败记录，不能伪装为 success；失败 trace 必须保留到 runner 记录。
- **OUT-006**：答案归一化只能处理可证明安全的表示差异；语义句、无法证明等价的符号式和歧义多解保持 `unknown`，不能为提高分数做激进重写。

### 4.4 截断与预算

- **TRUNC-001**：`finish_reason=length/max_tokens` 的候选、反思和工具回复在恢复前必须隔离，原文本不得进入验证、聚合或最终推理。
- **TRUNC-002**：每个截断事件必须记录阶段、候选编号、usage、是否已有首行答案和恢复状态，不记录完整残缺响应。
- **TRUNC-003**：恢复正常结束且具有显式答案后才可替换原候选；恢复再次截断或格式异常时，两份文本都退出正常聚合。
- **TRUNC-004**：verifier 截断可紧凑重试一次，再失败记 `unknown`；critic 截断直接丢弃；不得把残缺 verifier 当 `fail` 或用残缺 critic 触发反思。
- **TRUNC-005**：所有正常候选不可用时最多进行一次整题紧急答案调用；紧急回复若截断，只能提取首行显式答案，不能输出其残缺推理。
- **TRUNC-006**：请求级截断点估计和单侧 95% Wilson 上界都必须低于 5%，候选生成阶段自身截断率也低于 5%；恢复覆盖率 100%、残句泄漏 0、`invalid=0`。约 1082 次请求时截断最多约 42 次。
- **TRUNC-007**：恢复请求不得用于稀释总体比例，也不得绕过请求、token、工具和 deadline 预算。
- **TRUNC-008**：压缩推理不能以明显低于约 22% 的历史隐藏集基线为代价；能力判定仍需逐题配对和重复运行。

### 4.5 P1 验证与候选选择

- **VER-001**：只有封闭数值表达式、明确数域的有限方程解集、导数、不定积分、极限、留数、数值行列式、模幂和组合数等受支持结构才生成强验证计划。
- **VER-002**：证明、复合目标、数域不明、整数/正根等额外约束和无法安全解析的题必须保持无强计划或 `unknown`。
- **VER-003**：确定性验证在可终止子进程中执行并占用共享工具预算，结果只允许 `pass/fail/unknown`。
- **VER-004**：仅当一个或多个 `pass` 指向同一 canonical answer 时优先；证据冲突、只有 `fail/unknown`、超时、预算不足或解析失败都回退多数票/置信度规则。
- **VER-005**：确定性 verifier 不是任意题型的真值 oracle；扩大支持范围必须增加严格解析、正反例、漏根/增根、数域、超时和冲突测试。
- **VER-006**：关闭 `enable_deterministic_verification` 必须完整恢复 P0 选择行为，以支持单变量 A/B。

### 4.6 架构与状态

- **ARC-001**：`math_agent/` 是唯一运行实现；根 `user_agent.py` 只做官方兼容导出，`main.py`、`demo.py`、`verify_math.py` 只做适配。
- **ARC-002**：每次 `solve()` 创建独占 `SolveContext`，显式持有 problem、metadata、trace、budget 和 gateway；单题状态不得写回 Agent 实例。
- **ARC-003**：`agent.py` 只负责输入校验、上下文创建、异常收敛和兼容转发；阶段逻辑必须留在 `solver.py` 及聚焦模块。
- **ARC-004**：候选生成/恢复、评估/反思、选择、格式化、路由和模型消息适配保持职责分离；不得重建集中式巨型 Agent。
- **ARC-005**：新增、删除或移动运行模块时必须同步实验 `RUNTIME_FILES` 指纹与结构测试，避免实验冻结漏算实际代码。
- **ARC-006**：公开类型只保留一个对象来源；兼容门面重导出必须通过对象身份测试。
- **ARC-007**：架构变化必须同步 `ARCHITECTURE.md`、README、工程规范、相关测试和审计记录；不得新建第二份架构事实源。

### 4.7 数学工具与执行安全

- **TOOL-001**：`math_tools.py` 仅为兼容门面；解析、实现、schema/分发、模型循环和进程执行分别属于既定模块。
- **TOOL-002**：模型工具名、JSON、参数、表达式、矩阵、整数、指数和返回文本一律不可信；必须先做长度、类型、范围和复杂度检查。
- **TOOL-003**：不得引入 unrestricted `eval`、`exec`、`sympify` 或 `parse_expr`；SymPy 只能通过无 builtins 的显式白名单。
- **TOOL-004**：工具 schema 与实现必须一一对应；未知工具、畸形 JSON、越界、超时和子进程错误必须返回受控失败。
- **TOOL-005**：所有工具和确定性验证都必须在可终止子进程中执行，并保留墙钟硬超时和共享工具预算。
- **TOOL-006**：现有表达式、参数、结果、矩阵、整数、指数、组合数和单轮工具数量边界不得静默放宽；放宽必须有资源与恶意输入测试。

### 4.8 Runner、数据与评测

- **RUN-001**：JSONL、`idx` 和 checkpoint 均不可信；`idx` 必须经过白名单验证，输出路径必须留在指定目录。
- **RUN-002**：结果使用同目录临时文件和原子替换；只有合法 JSON、`status=success` 且非空 `final_response` 才可作为自动恢复 checkpoint。
- **RUN-003**：正式运行使用全新输出目录；断点恢复只能处理同一冻结运行的机器生成文件，不得接受人工预置结果。
- **RUN-004**：运行摘要记录输入文件名/SHA-256、模型、并发、开始时间、耗时和状态计数，不保存题面或密钥。
- **EVAL-001**：评测代码只放在 `evaluation/data`、`evaluation/scoring`、`evaluation/experiments`，共享 I/O 使用 `evaluation/io_utils.py`，CLI 使用 `python -m evaluation.<group>.<module>`。
- **EVAL-002**：每条正式基准必须有 source、license、split、level/难度和稳定 idx；缺失时不得称为正式、私有、held-out 或大学竞赛代表集。
- **EVAL-003**：必须审计内部重复、模板/近似重复，以及与 prompt few-shot、公开样例、开发集和其他 split 的重合。
- **EVAL-004**：内部合成题只能称为内部压力/回归集；公开 PutnamBench 只能证明同一公开题上的相对变化，不能证明预训练独立。
- **EVAL-005**：自动判分不得使用双向子串包含或不受限符号解析；无法证明的数学/语义等价为 `unknown`，不能自动算 `correct`。
- **EVAL-006**：证明和开放语义题的人工裁决必须匿名、对称并独立保存；人工复核不得回写模型答案或混入自动正确率。
- **EVAL-007**：能力比较必须同题配对，固定数据、commit、模型、配置、并发和重复次数；至少报告逐题转移、区间、请求、token、延迟、错误和截断，不能只比较两个总分。
- **EVAL-008**：随机模型一次运行不能证明提升；正式声明前至少按冻结协议重复 3 次，并使用可用的配对统计。
- **EVAL-009**：真实 API 测试必须先声明预计请求上限并获得用户授权；默认测试、CI、质量门禁和文档检查绝不调用模型端点。

### 4.9 依赖、CI、发布与版本控制

- **DEP-001**：`requirements*.txt` 是直接依赖输入，`.lock` 是完整安装产物；修改输入后必须同时重生成精确版本和 SHA-256 哈希。
- **DEP-002**：共享开发锁必须在最低支持 Python 3.10 的真实解释器中安装，并执行目标 marker 闭包；`--python-version` 交叉 dry-run 不能替代真实安装。
- **DEP-003**：核心与开发支持 Python 3.10+；可选 Demo 为避免已知 Pillow 漏洞要求 Python 3.12+，不得为兼容旧解释器回退到已知脆弱版本。
- **QUAL-001**：`scripts.run_quality_gates` 是唯一完整离线质量入口；必需检查、70% 覆盖率门槛和依赖审计不得为通过而删除或弱化。
- **QUAL-002**：无网络时 `--skip-dependency-audit` 只产生诊断报告，不能授权 formal 发布。
- **QUAL-003**：CI 必须在 Python 3.10/3.12 使用哈希锁；GitHub Actions 固定完整 SHA、权限 `contents: read`、checkout 不持久化凭据，且不得使用 `pull_request_target` 执行不可信代码。
- **QUAL-004**：临时目录和漏洞缓存必须位于忽略的 `.quality/` 独立子目录，避免跨权限残留污染后续检查。
- **REL-001**：formal 包要求干净 Git 工作树、同一 commit/tree 的完整通过报告、依赖审计和竞赛合规检查；源文件必须读取该提交的 Git blob。
- **REL-002**：脏工作树或显式 `--allow-dirty` 只能生成 `draft`，永远不得改名或解释为 formal。
- **REL-003**：`.env`、outputs、私有数据、`.quality`、dist、缓存、虚拟环境、符号链接、二进制伪装和超限文件不得进入发布包。
- **REL-004**：发布 manifest 必须保存来源、模型、手册哈希、默认配置、依赖锁、质量摘要和逐文件哈希；ZIP 旁必须提供 SHA-256。
- **REL-005**：项目当前保留所有权利。切换开源许可证或改变第三方数据/依赖权利声明必须获得所有者明确授权。
- **VCS-001**：开始修改前检查工作树并保留用户未提交内容；推送前 fetch 并确认远端基线，不得用 force push 覆盖未知远程提交。
- **VCS-002**：提交身份、目标远程和分支必须在推送前核对；提交后确认本地 HEAD 与远程跟踪引用一致。

## 7. 每次任务的强制流程

1. 读取 `git status`，确认并保护未提交内容。
2. 读取 `AGENTS.md`、本文件；涉及运行行为时再读 `ARCHITECTURE.md`，涉及比赛/提交时再读 `COMPETITION_COMPLIANCE.md`。
3. 在变更说明中列出受影响的规则 ID、已知问题 ID、保持不变的策略参数和验证计划。
4. 先添加能复现缺陷的离线回归，再修改实现；结构迁移必须对比迁移前后的请求序列和配置。
5. 迭代时运行最小测试，完成后运行 `python -m scripts.run_quality_gates`。真实 API 不属于默认验证。
6. 更新 README、唯一架构文档、工程规范、合规规范或审计记录中实际受影响的部分；没有影响时不要机械复制内容。
7. 推送前确认身份、远程、分支，先 fetch；禁止覆盖未知远程提交。
8. formal 交付必须在目标干净提交重新运行含依赖审计的完整门禁，再执行 `python -m scripts.build_release` 并核对 manifest 与 SHA-256。

## 8. 能力与合规声明边界

允许的表述必须与证据强度一致：

- 离线测试通过：只能说明已覆盖的确定性工程行为通过。
- 内部合成集高分：只能说明该内部模板/压力集已趋于饱和。
- 公开 PutnamBench 配对提升：只能说明该公开题集上的相对变化，不能证明预训练独立。
- 单次隐藏集分数：只能作为一次观测；没有逐题配对和重复时不能证明显著提升/回退。
- `request_count=0` 的官方结果：只能说明入口失败，不能进入能力趋势。
- 截断压力门禁通过：说明可靠性指标通过，不说明数学答案正确。
- 手册与离线合规门禁通过：说明已落实可自动检查的边界，不能证明人员在代码外从未违规。

任何“能力提高”“正式合规”“已解决线上问题”声明，都必须链接相应冻结报告，并明确仍未验证的边界。
